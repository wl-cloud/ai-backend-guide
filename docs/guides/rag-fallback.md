# RAG 拒答 / 兜底策略

::: tip 这篇讲什么
用户问的问题，一定有很大比例"资料里没有"。这时候系统怎么表现，直接决定它是"靠谱工具"还是"一本正经胡说八道"。这篇讲一套可落地的兜底方案。
:::

## 一、核心原则

### 原则 1：不编造

先记住一条底线，它比任何技术细节都重要：

> **资料里没有，就明确说不知道；绝不硬编一个看起来像答案的东西。**

「资料里没有」和「模型能不能回答」是两件事。模型可以用通用知识回答，但必须**标注清楚**这不是来自你的知识库。这条线一旦模糊，用户的信任就崩了。

### 原则 2：资料降权 + 冲突即拒答

除了「有没有」，还要看「可不可信」：

- **待验核的资料降权**：对未核实、来源不明、可信度存疑的资料，降低其权重，不当作确定结论引用。
- **可信资料冲突时如实说不知道**：当多个可信来源互相矛盾、无法判定孰对时，明确说「我不知道 / 无法确定」，不要硬选一个答案。

一句话：**宁可明确说不知道，也不在信息不可靠或相互冲突时给出武断结论。**

## 二、三层机制

兜底不是加一句"不知道就说不知道"就完事，而是三层机制配合：

```
检索置信度阈值 → 分场景兜底 → 提示词硬约束
```

### 第 1 层：置信度阈值，判断"有没有命中"

检索会返回一批结果和相似度分数。当最高分数**低于阈值**时，就判定"资料里没有"，触发兜底：

```python
def retrieve(question):
    hits = vector_db.search(query_embedding, top_k=5)   # 带相似度分数
    best_score = hits[0].score if hits else 0
    if best_score < THRESHOLD:        # 低于阈值 → 判定没命中
        return None
    return hits
```

**阈值怎么定**：别拍脑袋。攒一批测试问句，人工标"命中/未命中"，看分数的分布再切。

### 第 2 层：分场景兜底

判定"没有"之后，按风险等级走不同兜底：

| 场景 | 例子 | 兜底方式 |
|------|------|----------|
| 高风险（医疗/法律/金融） | "这个药能吃吗" | 明确拒答 + 建议咨询专业渠道 |
| 中风险（事实/业务） | "XX 政策是什么" | 说明资料中无此内容 + 追问澄清 / 转人工 |
| 低风险（通用闲聊） | "今天天气如何" | 用通用知识回答，但标注"非资料内容" |

```python
def fallback(question, category):
    if category == "high_risk":
        return "抱歉，涉及专业问题，我无法回答，建议咨询专业人士。"
    if category == "medium_risk":
        return "资料中暂时没有相关内容。你是指……吗？可以换个说法再试试。"
    # low_risk：用通用知识回答，但明确标注
    return "（以下内容非来自知识库，仅供参考）" + generic_answer(question)
```

### 第 3 层：提示词硬约束，兜住最后一道

即使检索到了内容，也要在 Prompt 里约束模型不越界：

```python
system = """你只能根据给定的资料回答。
- 资料里有答案 → 基于资料回答，并给出依据。
- 资料里没有 → 明确回答「我不知道」，禁止编造。
- 永远不要假装资料里有不存在的信息。"""
```

## 三、可勾选的落地清单

- [ ] 检索结果带相似度分数，且有明确阈值
- [ ] 低于阈值时走兜底，而不是硬塞最相近的一段
- [ ] 高风险领域（医疗/法律/金融）默认拒答
- [ ] 兜底话术是固定模板（保证一致性、可审计）
- [ ] 用通用知识兜底时，明确标注"非知识库内容"
- [ ] Prompt 里有"仅依据资料 + 不知道就说不知道"的硬约束
- [ ] 回答附引用来源，检索不到的部分明确标注
- [ ] 待验核/来源不明的资料降权处理
- [ ] 可信资料冲突时，如实回答"不知道/无法确定"
- [ ] 用评测集持续监控"拒答是否准确、是否误拒/漏拒"

## 四、常见坑

- ❌ **没有阈值，永远返回"最相近"的一条** → 问啥都硬答，必然胡编。
- ❌ **兜底话术临时发挥** → 每次说法不一，用户感知混乱，也难审计。
- ❌ **高风险领域让通用模型兜底** → 医疗/法律/金融答错代价大，必须拒答。
- ❌ **只做输入侧兜底，不看输出** → 模型仍可能"答非所问"，要配合[护栏](/terms/eval/guardrails.md)和输出校验。
- ❌ **资料冲突时硬选一个答案** → 多个来源矛盾时，如实说"无法确定"比"猜一个"更可信；待验核资料应降权而非照单全收。

## 五、小结

一句话总结：**用阈值判断"有没有"，按风险分场景兜底，用 Prompt 硬约束防编造，待验核资料降权、可信资料冲突时如实说"不知道"，再靠评测持续校准。** 这些做到，你的 RAG 系统就是一个"不懂就直说、拿不准就不乱说"的靠谱工具，而不是一个"什么都敢说"的定时炸弹。
