# 幻觉（Hallucination）

::: tip 一句话定义
幻觉（Hallucination）是指大模型生成的内容看起来通顺、自信，但事实错误或凭空捏造——俗称「一本正经地胡说八道」。
:::

## 详细解释

幻觉的根源在于 LLM 的工作方式：它不是在「查证事实」，而是在「预测下一个最可能的词」。当它不确定时，仍会生成一个最像正确答案的东西，于是编出不存在的人名、文献、API。

对后端开发，幻觉是**必须处理的风险**，常见缓解手段：

- **RAG**：让回答基于检索到的真实资料。
- **约束 Prompt**：明确要求「不知道就说不知道，禁止编造」。
- **结构化输出**：限定输出格式，减少自由发挥。
- **人工 / 自动评测**：用评测集持续监控。

## 生活化类比

幻觉就像**自信过头的同学**：被点名提问，没背到，也要硬编一个顺口的答案，语气还特别肯定。你要么给他开卷（RAG），要么提前教他「不会就说不会」。

## 代码示例

```python
# 用 System Prompt 抑制幻觉
messages = [
    {"role": "system", "content": "你只能根据给定的资料回答；资料里没有的，请明确说「我不知道」，禁止编造。"},
    {"role": "user", "content": f"资料：{context}\n\n问题：{question}"},
]
```

## 常见误区

- ❌ 「换个更强的模型就没幻觉了」→ 更强只是概率更低，幻觉无法根除，工程上仍要兜底。
- ❌ 「幻觉只在闲聊里有」→ 代码生成里也会编出不存在的 API、参数。
- ❌ 「RAG 之后就高枕无忧」→ 检索错、资料错，照样会输出错误答案，需配合评测。
